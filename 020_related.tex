В настоящем разделе будет представлен обзор предметной области.

\subsection{RISC-V}
RISC-V --- свободная и открытая архитектура процессоров, впервые представленная в 2010 году в университете Беркли, США \cite{waterman2016design}.
Создана по концепции RISC (Reduced Instruction Set Computer) \cite{jamil1995risc}, то есть обладает довольно скромным набором инструкций, но с возможностью дополнения при помощи расширений.


\subsection{Sail}
Эмулятор архитектуры --- это инструмент, который позволяет исполнять программу для одной архитектуры на процессоре другой (или той же) архитектуры.
Sail --- это язык для определения эмуляторов процессорных архитектур.
На языке Sail реализованы модели множества архитектур, включая X86\footnote{\url{https://github.com/rems-project/sail-x86-from-acl2} (дата обращения: \DTMdate{2025-02-17}).}, Arm\footnote{\url{https://github.com/rems-project/sail-arm} (дата обращения: \DTMdate{2025-02-17}).} \cite{armstrong2019isa}, RISC-V\footnote{\url{https://github.com/riscv/sail-riscv} (дата обращения: \DTMdate{2025-02-17}).} \cite{armstrong2019isa} и другие.
По моделям на данном языке Sail умеет генерировать эмулятор на \OCaml{} или \C{}.
Кроме генерации эмуляторов по моделям, Sail также позволяет генерировать и исполнять автоматические тесты, исполнять тесты безопасности кода, а также верифицировать модели ISA.

\subsubsection{Модель sail-riscv}
Sail-riscv --- это формальная модель RISC-V ISA, реализованная на языке Sail.
Модель представляет из себя интерпретатор инструкций RISC-V ISA.

Во-первых, в модели для удобного внутреннего пред\-ставления инструкций определяется дерево абстрактного синтаксиса (Ab\-stract Syntax Tree).
Причём один узел AST может представлять множество инструкций.
Например, на листинге \ref{itype} узел \texttt{ITYPE}, который параметризован 12-ти битным непосредственным (immediate) значением, индексами выходного и входного регистров и интерпретируемой операцией, представляет инструкции \texttt{addi}, \texttt{slti}, \texttt{sltiu}, \texttt{xori}, \texttt{ori} и \texttt{andi}.

% \bigbreak
% \bigbreak

\begin{lstlisting}[caption={Пример определения узла AST в sail-riscv}, language=sail, frame=single, label=itype]
  enum iop = {RISCV_ADDI, RISCV_SLTI, RISCV_SLTIU,
              RISCV_XORI, RISCV_ORI, RISCV_ANDI}

  union clause ast = ITYPE : (bits(12), regidx, regidx, iop)
\end{lstlisting}

Затем для каждого узла AST определяются \texttt{encdec} отображения, которые предназначены для декодирования 32-битного кода инструкции (opcode) в параметризованный узел AST модели и, наоборот, кодирования параметризованного узла AST в код инструкции.

\begin{lstlisting}[caption={Пример определения функции кодирования и декодирования инструкций в sail-riscv}, language=sail, frame=single, label=encdec_itype]
  mapping encdec_iop : iop <-> bits(3) = {
    RISCV_ADDI  <-> 0b000,
    RISCV_SLTI  <-> 0b010,
    RISCV_SLTIU <-> 0b011,
    RISCV_ANDI  <-> 0b111,
    RISCV_ORI   <-> 0b110,
    RISCV_XORI  <-> 0b100
  }

  mapping clause encdec = ITYPE(imm, rs1, rd, op)
    <-> imm @ rs1 @ encdec_iop(op) @ rd @ 0b0010011
\end{lstlisting}
На листинге \ref{encdec_itype} представлено определение такого отображения для узла \texttt{ITYPE}.
Из определения этого отображения видно, что первые 12 бит кода инструкции кодируют непосредственное значение, следующие 5 бит кодируют входной регистр, следующие 3 бита кодируют целочисленную операцию, которую будет представлять узел \texttt{ITYPE}, следующие 5 бит кодируют выходной регистр.

Код, который отвечает за определение семантики исполнения инструкции, содержится в \texttt{execute} функциях.
% Функции \texttt{execute} в качестве аргумента принимают параметризованный узел AST.

\begin{lstlisting}[caption={Пример определения семантики исполнения инструкций \texttt{addi}, \texttt{slti}, \texttt{sltiu}, \texttt{xori}, \texttt{ori} и \texttt{andi} в sail-riscv}, language=sail, frame=single, label=execute_itype]
function clause execute (ITYPE (imm, rs1, rd, op)) = {
  let rs1_val = X(rs1);               // read the rs1
  let immext : xlenbits = EXTS(imm);  // sign-extend imm
  let result : xlenbits = match op {  // compute the result
    RISCV_ADDI  => rs1_val + immext,  // for addi, do addition
    RISCV_SLTI  => EXTZ(rs1_val <_s immext), // ...etc
    RISCV_SLTIU => EXTZ(rs1_val <_u immext),
    RISCV_ANDI  => rs1_val & immext,
    RISCV_ORI   => rs1_val | immext,
    RISCV_XORI  => rs1_val ^ immext
  };
  X(rd) = result;                     // write result to rd
  RETIRE_SUCCESS                      // successful termination
}
\end{lstlisting}

На листинге \ref{execute_itype} определена функция, которая задаёт семантику исполнения для узла \texttt{ITYPE}.
Семантика следующая, во-первых, считывается значение из входного регистра \texttt{rs1}, затем знаково расширяется непосредственное значение до ширины равной \texttt{XLEN} (текущей разрядности RISC-V), далее в зависимости от параметра \texttt{op}, представляющего целочисленную операцию, вычисляется результат, в конце вычисленный результат записывается в выходной регистр \texttt{rd}.

Наконец, для каждого узла AST определяются функции \texttt{assembly}, отображающие параметризованные узлы AST в мнемоники.
На листинге \ref{itype_assembly} определена такая функция для узла \texttt{ITYPE}.
Из определения видно, что узел \texttt{ITYPE} отображается в зависимости от параметра \texttt{op} в конкретную целочисленную инструкцию с непосредственным операндом.

\begin{lstlisting}[caption={Пример определения функции отображения параметризованного узла AST в мнемонику в sail-riscv}, language=sail, frame=single, label=itype_assembly]
  mapping itype_mnemonic : iop <-> string = {
    RISCV_ADDI  <-> "addi",
    RISCV_SLTI  <-> "slti",
    RISCV_SLTIU <-> "sltiu",
    RISCV_XORI  <-> "xori",
    RISCV_ORI   <-> "ori",
    RISCV_ANDI  <-> "andi"
  }

  mapping clause assembly = ITYPE(imm, rs1, rd, op)
    <-> itype_mnemonic(op) ^ spc() ^ reg_name(rd) ^ sep()
        ^ reg_name(rs1) ^ sep() ^ hex_bits_signed_12(imm)
\end{lstlisting}

\subsection{LLVM TableGen}

LLVM \cite{lattner2004llvm} --- это инфраструктура для разработки компиляторов, созданная в 2003 году в Иллинойсском университете, США.
LLVM поддерживает широкий спектр целевых платформ, включая RISC-V.
Важную роль для бэкендов LLVM играет TableGen.

TableGen --- это декларативный язык, который используется в LLVM для описания предметно-ориентированной информации.
В частности, TableGen используется для описания спецификации ISA целевой платформы.
Информация о спецификации ISA целевой платформы из TableGen файлов используется в бэкендах LLVM.
Файлы TableGen имеют расширение \texttt{.td}.
При помощи утилиты \texttt{llvm-tblgen} можно скомпилировать \texttt{.td} файлы в \texttt{JSON}.

\begin{lstlisting}[caption={Описание инструкции addi при помощи TableGen}, language=tblgen, frame=single, mathescape=true, label=addi_td]
let hasSideEffects = 0, mayLoad = 0, mayStore = 0 in
class ALU_ri<bits<3> funct3, string opcodestr>
    : RVInstI<funct3, OPC_OP_IMM, (outs GPR:$\dollar$rd),
        (ins GPR:$\dollar$rs1, simm12:$\dollar$imm12),
        opcodestr, "$\dollar$rd, $\dollar$rs1, $\dollar$imm12">,
        Sched<[WriteIALU, ReadIALU]>;

let isReMaterializable = 1, isAsCheapAsAMove = 1 in
def ADDI  : ALU_ri<0b000, "addi">;
\end{lstlisting}

В описании инструкции на TableGen постулируются следующие свойства:
\begin{itemize}
  \item входные и выходные операнды, т.~е. операнды, из которых считываются и в которые записываются значения соответственно;
  \item может ли инструкция читать или писать память;
  \item коммутативность;
  \item сложность;
  \item и множество других свойств.
\end{itemize}

Например, на листинге \ref{addi_td} представлено описание инструкции \texttt{addi}. В описании инструкции говорится, например, что первый операнд (\texttt{rd} --- register destination) является выходным, а два остальных (\texttt{rs1} --- register source и \texttt{imm} --- непосредственное значение) входными, инструкция не читает (\texttt{mayLoad} = 0) и не пишет (\texttt{mayStore} = 0) память, инструкция не имеет побочных эффектов.
