% Risc-v на сегодняшний день является одной из наиболее активно развивающихся открытых архитектур.

% Важную роль в экосистеме risc-v играет проект LLVM. LLVM --- инфраструктура для создания компиляторов. LLVM имеет множество целевых плафторм, в том числе и RISC-V. Спецификация ISA целевой архитектуры описывается в LLVM декларативно, на специальном декларативном языке, который называется TableGen.

% Одноврменно, существует язык Sail, предназначенный для определения моделей процессорных архитектур. Существует формальная

% Одноврменно, существует язык Sail, предназначенный для определения моделей процессорных архитектур. На Sail существует оффициальная, одобренная сообществом risc-v foundation модель risc-v isa. Модель представляет из себя поведенческую спецификацию.

% Несмотря на наличие двух независимых спецификаций RISC-V ISA, в настоящее время не существует инструментов, позволяющих систематически сопоставлять эти спецификации и проверять их согласованность. Это создаёт риск накопления расхождений по мере их эволюции.
% Наличие расхождений может приводить к некорректной генерации кода компилятором и снижению общей надёжности экосистемы RISC-V. Поэтому актуальна проблема валидации спецификаций относительно друг друга

\begin{frame}{Введение}
    \begin{itemize}
        \item RISC-V --- открытая, расширяемая ISA (Instruction Set Architecture)
        \item LLVM\footnote[frame]{\url{https://llvm.org}} --- инфраструктура для компиляторов
        \begin{itemize}
            \item Спецификация ISA описывается декларативно на TableGen
        \end{itemize}
        \item Sail\footnote[frame]{\url{https://github.com/rems-project/sail/}} --- язык для описания моделей процессорных архитектур. Позволяет задать семантику исполнения процессорных инструкций
        \begin{itemize}
            \item sail-riscv\footnote[frame]{\url{https://github.com/riscv/sail-riscv}} --- формальная, поведенческая спецификация RISC-V ISA
        \end{itemize}
        \item Актуальна проблема валидации спецификаций относительно друг друга
    \end{itemize}
\end{frame}

\begin{frame}[fragile]{Обзор. Sail-riscv}

    Реализация модели архитектуры RISC-V на Sail состоит из:
    \begin{itemize}
        \item \texttt{AST}, причём один узел может представлять множество инструкций

        \item \texttt{encdec} функции, задающие отображения opcode в узел AST

        \item \texttt{execute} функции, задающие семантику исполнения
        \item \texttt{assembly} функции, отображающие узлы AST в строки
\begin{lstlisting}[caption={}, language={}, frame=single, mathescape = true]
function clause execute (ADDI(imm, rs1, rd)) = {
    let rs1_val = X(rs1);               // read the rs1
    let immext : xlenbits = EXTS(imm);  // sign-extend imm
    let result : xlenbits = rs1_val + immext; // compute
    X(rd) = result;                  // write result to rd
    RETIRE_SUCCESS
}
\end{lstlisting}

    \end{itemize}

\end{frame}

\begin{frame}{Реализация. Обращения инструкции к памяти}

    \begin{itemize}
        \item Для работы с памятью в sail-riscv используются функции \texttt{read\_ram} и \texttt{write\_ram}
        \item Для того чтобы определить работает ли инструкция с памятью, для каждой функции \texttt{execute} проверялась достижимость вершин \texttt{read\_ram} и \texttt{write\_ram} в графе вызовов всех функций
        \vspace{1em}
        \item Однако любой инструкции, работающей с адресами, необходимо транслировать виртуальный адрес в физический
        \begin{itemize}
            \item Чтение из памяти могло происходить в случае, если при трансляции адреса происходил TLB miss. Тогда необходимо было прочитать таблицу виртуальных адресов из памяти
            \item Запись в память могла происходить тогда, когда при трансляции адреса необходимо было обновить специальные биты (A или D) у записи в таблице виртуальных адресов
        \end{itemize}
    \end{itemize}

\end{frame}

\begin{frame}[fragile]{Реализация. Особенности sail-riscv-p}

    \begin{itemize}
        \item Sail-riscv-p\footnote[frame]{\url{https://github.com/umcann123/sail-riscv-p}} --- это форк sail-riscv с реализацией расширения P (packed SIMD)
        \item Для RV32 регистры могут интерпретироваться как пара
\begin{lstlisting}[caption={}, language=Caml, frame=single]
function clause execute(PEXT_64BITS_ADD_SUB(rs2, rs1, rd, op))
...
    rs1_val = X(rs1 | 0b00001) @ X(rs1 & 0b11110);
...
\end{lstlisting}
        \begin{enumerate}
            \item Модель представлялась в ANF форме
            \item Определялись входные и выходные операнды по графу вызовов
            \item Построение и анализ data flow графа --- определение зависимости операндов найденных на предыдущем шаге
\begin{lstlisting}[caption={}, language=Caml, frame=single]
let a1 = rs1 | 0b00001 in
let a2 = rs1 & 0b11110 in
rs1_val = X(a1) @ X(a2);
\end{lstlisting}

        \end{enumerate}
    \end{itemize}

\end{frame}
